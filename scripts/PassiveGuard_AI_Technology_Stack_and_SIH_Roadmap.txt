PART 1 — PROJECT AT A GLANCE
============================================================
What PassiveGuard AI Does: PassiveGuard AI is an autonomous, passive threat detection and SOC monitoring system designed specifically for unidirectional (one-way) network boundaries. It ingests mirror/TAP traffic without sending a single packet back, extracting rich flow, temporal, DNS, and TLS metadata, and applying a hybrid statistical + machine learning detection pipeline to flag enterprise and industrial cyber threats in real time.
Who It Is Designed For: High-security critical infrastructure (ICS/SCADA), defense networks, power grids, financial datacenters, and enterprise SOCs operating under strict unidirectional isolation constraints (e.g., optical data diodes).
Why Unidirectional / Passive Monitoring Matters: Active network probing, TCP SYN scanning, or inline packet blocking is physically impossible or strictly forbidden on data diodes and high-assurance security perimeters. Traditional active security tools break diode isolation or create covert return channels. PassiveGuard AI strictly operates in an observation-only mode.
What Makes It Different: It combines zero-packet-transmission passive observation with a hybrid detection engine: combining deterministic statistical thresholding (for rapid volume & entropy anomalies) with scikit-learn Machine Learning (RandomForest / GradientBoosting) for complex behavioral patterns (C2, DGA, Exfiltration, Encrypted Malware).
What AI/ML Contributes: Machine learning identifies subtle statistical patterns in encrypted traffic, domain name n-gram entropy, and inter-arrival timing jitter that deterministic rules miss, while suppressing false positives across multi-stage attack scenarios.
What the Current Prototype Demonstrates: A fully functional, cloud-deployed SOC dashboard showing live flow ingestion, real-time threat detection across 7 threat vectors, interactive simulation replay, model performance metadata registry, and instant alert state synchronization over WebSockets.

PART 9 — AI/ML TECHNOLOGY & HYBRID DETECTION ENGINE
============================================================
PassiveGuard AI uses a hybrid statistical + machine learning architecture. Deterministic rules catch immediate volumetric or protocol violations with zero false negatives, while ML models catch subtle behavioral patterns in encrypted or randomized traffic.
Statistical Layer: Evaluates sliding-window packet counts, byte rates, inter-arrival time standard deviation, and domain Shannon entropy.
Machine Learning Layer: Scikit-Learn Random Forest classifiers operating on 15+ normalized feature vectors extracted from passive flows.
Risk Fusion Engine: Combines statistical rule scores and ML inference probabilities using a weighted fusion formula to yield a composite 0-100 risk score.

PART 11 — DATASET ANALYSIS & UNSW-NB15 LABEL MAPPING
============================================================
UNSW-NB15 Dataset Selection: Selected for its realistic hybrid modern network traffic synthesized by the Australian Centre for Cyber Security (ACCS). It contains authentic low-level attack behaviors across modern protocols.
Crucial Label Mapping Clarification: In UNSW-NB15, volumetric attacks are categorized under the 'DoS' label. To match modern enterprise SOC taxonomy, PassiveGuard AI's ingestion pipeline maps the dataset's 'DoS' class directly to the canonical 'DDOS' detection class during model training and evaluation.

PART 14 — REAL-TIME STREAMING & REPLAY INFRASTRUCTURE
============================================================
Real-time telemetry is achieved by sliding-window flow aggregation. The backend processes incoming traffic streams in 1-second ticks, evaluating active flows against detection rules and immediately broadcasting state updates over WebSocket (`/ws`) to all connected UI clients.

============================================================
PART 15 — PASSIVE & UNIDIRECTIONAL SECURITY CONSTRAINTS
============================================================
PassiveGuard AI strictly adheres to unidirectional optical diode isolation principles:
• Zero Outbound Traffic: Absolutely no packets, TCP ACKs, SYN-ACKs, or probes are generated by the system.
• No Inline Interception: System operates entirely out-of-band via TAP/span port mirroring.
• No Payload Decryption: Respects privacy & TLS encryption by inspecting header metadata, packet lengths, and timing jitter only.
