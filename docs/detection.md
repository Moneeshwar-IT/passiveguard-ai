# PassiveGuard AI — Threat Detection Architecture & Methodology (Modules 3 – 9)

This document provides technical documentation for all passive threat detection engines and risk fusion pipelines implemented in PassiveGuard AI.

---

# Part 1: DDoS Detection Engine (Module 3)

## 1. Architecture Overview

The DDoS detector adopts a **hybrid dual-layer architecture**:
- **Layer A (Statistical Layer)**: Computes transparent, human-explainable heuristic indicators (SYN rate, SYN/ACK imbalance, UDP flood rates, directional asymmetry, source entropy).
- **Layer B (Machine Learning Layer)**: Evaluates a trained `RandomForestClassifier` model loaded from local disk.

---

# Part 2: C2 Beaconing Detection Engine (Module 4)

Command & Control (C2) beaconing represents automated, recurring network transmissions generated by compromised internal hosts to maintain persistent communication with remote C2 servers.

---

# Part 3: DGA Domain Detection Engine (Module 5)

Strips top-level domains (`.com`, `.org`, `.co.uk`, `.example`) to extract the Second-Level Domain (SLD). Evaluates Shannon entropy $H(X)$, length anomalies, digit ratios, and lexical distributions.

---

# Part 4: DNS Tunnelling Detection Engine (Module 5)

Groups DNS queries by `(source_ip, parent_domain)` over a sliding window (`DNSTunnelStateTracker`). Measures subdomain churn ratio, query length averages ($> 50$ chars), and payload entropy ($H(X) > 4.0$).

---

# Part 5: Encrypted-Session Malware Detection Engine (Module 6)

Operates strictly on unencrypted TLS Client Hello / Server Hello handshake metadata (TLS version, cipher suites, JA3/JA4 fingerprints) and IP/transport packet distributions with **zero payload decryption**.

---

# Part 6: Reconnaissance & Port Scanning Detection Engine (Module 7)

Identifies `VERTICAL` port scans, `HORIZONTAL` host sweeps, and `MIXED` scan patterns using passive flow fan-out statistics and TCP flag ratios.

---

# Part 7: Data Exfiltration Detection Engine (Module 8)

Analyzes directional byte volume asymmetries, sustained egress durations, and local destination access frequency without inspecting plaintext payloads.

---

## 2. Score Normalization & Weighting

Detector output scores are normalized to $[0.0, 1.0]$. Each detector contributes based on configured domain importance weights:

| Detector Name | Detector Code | Relative Weight |
| :--- | :--- | :--- |
| **C2 Detector** | `c2_detector` | 1.5 |
| **Exfiltration Detector** | `exfiltration_detector` | 1.4 |
| **DDoS Detector** | `ddos_detector` | 1.2 |
| **DNS Tunnel Detector** | `dns_tunneling_detector` | 1.1 |
| **Encrypted Malware Detector** | `tls_detector` | 1.1 |
| **DGA Detector** | `dga_detector` | 1.0 |
| **Reconnaissance Detector** | `recon_detector` | 0.8 |

---

## 3. Corroboration & Risk Score Calculation

The fused score incorporates peak detector contribution, weighted average, and a cross-detector corroboration bonus:

1. **Peak Contribution**: $S_{\text{max}} = \max_i(\text{norm\_score}_i)$
2. **Weighted Average**: $S_{\text{avg}} = \frac{\sum w_i \cdot \text{norm\_score}_i}{\sum w_i}$
3. **Corroboration Bonus**: $+0.08$ per additional independent detector active above threshold ($\ge 0.50$), capped at $+0.20$.
4. **Fused Score**:
   $$\text{FusedScore} = \min\left(1.0, (0.6 \cdot S_{\text{max}}) + (0.4 \cdot S_{\text{avg}}) + \text{Bonus}\right)$$

---

## 4. Primary vs Corroborating Threat Selection

- **Primary Threat Class**: Selected from the non-benign detector yielding the highest normalized risk score.
- **Corroborating Threat Classes**: All additional active detectors scoring $\ge 0.50$ are preserved in `corroborating_threats`.

---

## 5. Confidence vs Risk

- **Risk Score**: Quantifies behavioral severity ($0.0 \le S \le 1.0$).
- **Confidence Score**: Quantifies evidence quality and multi-detector corroboration depth:
  $$\text{Confidence} = \min\left(1.0, 0.40 + 0.15 \cdot N_{\text{detectors}} + 0.20 \cdot S_{\text{max}}\right)$$

---

## 6. Alert Deduplication

- Key: `(source_ip, destination_ip, threat_class)`
- Cooldown: `cooldown_sec = 60.0`
- Suppresses repetitive identical alerts within the cooldown window while immediately allowing distinct threat classes or destination target IPs.
